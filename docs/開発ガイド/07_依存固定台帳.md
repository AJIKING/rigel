# 07. 依存固定台帳 — なぜそのバージョンに固定しているか

> 依存を上げて何かが壊れたとき・上げようか迷ったとき、**最初にここを読む**。
> 固定（pin / override / ペア制約)には全て理由がある。理由が消えたら固定も外す。
> 逆に、ここに載っていない依存は「安全枠」＝ゲート（typecheck/lint/test/build）が
> 緑なら patch/minor をいつ上げてもよい。
>
> 保守ルール: 固定・override を追加/変更/削除したら**このファイルを同じコミットで更新**する。

## 運用（3層）

| 層 | 対象 | 上げ方 |
|---|---|---|
| 安全枠 | この台帳に載っていないもの | 定期バッチで patch/minor をまとめて。ゲート緑で即コミット |
| 中間枠 | メジャー跨ぎ（vitest/jest/eslint/TS など） | 1件=1コミット。下の「保留中」の解除条件を先に確認 |
| 凍結枠 | 下の「固定中」のペア群 | 独立プロジェクト（docs/plans/ に Plan を書いてから） |

## 固定中（pnpm.overrides / 明示 pin）

### `tar: ">=7.5.11"`（ルート override）
- **理由**: セキュリティハードニング（P6, f730799）。tar v6 系の脆弱性回避。
- **解除条件**: 全依存が自然に tar >=7.5 を要求するようになったら不要。

### `@expo/cli>tar: "^6.2.1"`（スコープ付き override）
- **理由**: `@expo/cli`（SDK 52 の 0.22.x）は `require("tar").default.extract(...)` と
  v6 前提の呼び方をしており、上の override で v7 に昇格すると `.default` が undefined になり
  **expo prebuild がテンプレート展開で必ず失敗する**（2026-07 Codemagic ビルド障害の原因。e8e1426）。
  tar はビルド時ローカルツールで本番ランタイムには載らないためリスク限定。
- **解除条件**: Expo SDK 53+ へ移行（新しい @expo/cli は tar v7 対応）。

### `@types/react: "19.2.17"`（ルート override）
- **理由**: web(React 19) と mobile(React 18) が同居するモノレポで、@rigel/ui など共有層の
  React 型を1つに固定して型不整合を防ぐ。
- **解除条件**: mobile が React 19（= Expo SDK 53+）に揃ったら通常の semver 管理に戻せる。

### `@types/node: "22.20.1"`（ルート override）
- **理由**: engines（Node >= 22.12）に型を揃える。野放しだと依存経由で新しい
  @types/node が混ざり、フロアの Node に無い API が型上「ある」ことになる。
  実行系（ローカル/CI/deploy/Codemagic）は Node 24 だが、型はサポート下限に合わせる。
- **解除条件**: engines を上げるとき（型も同じメジャーへ同時更新）。

## 凍結枠（ペアで動く塊。単独で上げてはいけない）

### Expo SDK 52 一式（mobile）
`expo 52` / `react-native 0.76.5` / `react 18.3.1` / `react-test-renderer 18.3.1` /
`expo-*`（auth-session, crypto, image-picker, secure-store, status-bar, web-browser）/
`jest-expo 52` / `babel-preset-expo 12` / `react-native-screens 4.4` / `react-native-svg 15.8` /
`react-native-safe-area-context 4.12` / `@testing-library/react-native 12`
- **理由**: すべて SDK 52 の互換ペア。`npx expo install` が解決する版から単独で外すと
  実機/ビルドで壊れる（特に screens/svg/safe-area はネイティブモジュール）。
- **上げ方**: SDK 57 移行として一括（[docs/plans/expo-sdk-57.md](../plans/expo-sdk-57.md)）。
  移行すると `@expo/cli>tar` override・React 18/19 混在が全部解消される。
- **期限あり（2026-07-27 追記）**: この枠を維持したままでは **Android を Play に出せない**。
  SDK 52 の `targetSdkVersion` は 34 で、Play の下限は現在 35・**2026-08-31 以降は 36**。
  「安定してから上げる」対象ではなく、**Android リリースの前提条件**として扱うこと。

### `zod 3系`（@rigel/schema, api。manifest は `^3.24.1` — minor は安全枠、major(4) のみ凍結）
- **理由**: 牌譜スキーマは全層共有の背骨。zod 4 は破壊的変更（エラー形式・API）が広く、
  schema/api/ui/client/web/mobile へ同時に波及する。
- **上げ方**: 独立 Plan（[docs/plans/zod-4.md](../plans/zod-4.md)）。

### `next 15.5`（web）
- **理由**: OpenNext（@opennextjs/cloudflare）の対応バージョンと組で動く。
  next 16 は OpenNext 側の対応確認＋ cf:build / OGP（next/og）の実機検証が要る。
- **上げ方**: OpenNext の next 16 対応を確認してから1コミットで（cf:preview は Windows 不可の
  ため検証は CI/Linux ビルド＋本番デプロイの確認で行う）。

## 保留中（中間枠だが今はブロックされている）

| パッケージ | 現状→最新 | ブロック理由 | 解除条件 |
|---|---|---|---|
| jest / @types/jest | 29 → 30 | jest-expo 52 が jest 29 世代の内部依存 | Expo SDK 57 移行（jest-expo 57）と同時 |
| eslint | 9 → 10 | typescript-eslint v8 の peer が eslint ^8/^9 | typescript-eslint が eslint 10 対応したら |
| typescript | 5.7 → 7（ネイティブ tsc） | typescript-eslint / expo / next のエコシステム対応待ち | 主要ツールの TS7 対応が出揃ったら |
| react（mobile） | 18.3 → 19 | Expo SDK 52 ペア | SDK 57 移行と同時 |
| @vitejs/plugin-react | 5 → 6 | v6 は `vite/internal` を import（vite 8 系向け）。vite 7 では ERR_PACKAGE_PATH_NOT_EXPORTED | vite 8 へ上げるときにペアで |

> vitest 4 / vite 7 は導入済み。vite は vitest・plugin-react の **peer** なので、
> ルートと web の devDependencies に明示している（無いと lockfile の古い解決に固着する）。
> jsdom も同じ理由でルートと web の両方に明示（vitest の jsdom peer がルート側で解決されるため）。
