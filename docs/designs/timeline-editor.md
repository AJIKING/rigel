# 設計: 手順（タイムライン）エディタ

> 対象プロトタイプ: [../rigel-edit-timeline2.html](../rigel-edit-timeline2.html)
> 位置づけ: 編集画面に**新しいナビゲーション（手順タブ）**を追加し、**打牌（手出し/ツモ切り）と鳴きの時系列順・巡目**を編集できるようにする。
> このファイルは設計の単一真実源。`[決定]` は確定、`[未確定]` は要合意。矛盾する実装はしない。

---

## 1. 目的（何を可能にするか）

- 打牌・鳴きを**時系列イベント列**として一覧し、**行のドラッグで順番を入れ替え**できる。
- 各打牌の **席 / ツモ牌 / 捨て牌 / 手出し・ツモ切り** をタップで編集できる。
- **巡目**は「親の打牌ごとに +1」で自動区切り。順番の入れ替えで巡目も自動再計算される（＝巡目の順番も編集できる）。
- 鳴き（チー/ポン/大明槓/暗槓/加槓）を時系列の任意位置に挿入・編集できる。
- 既存の盤面エディタ（席ごとの直接編集）と**同じ牌譜**を両方向から編集できる。

---

## 2. 現行スキーマとのギャップ（ここが設計の核心）

現行 `Kifu`（`packages/schema`）は**静的スナップショット**:

- `seats[seat].river: Discard[]`（`order` は**席内**の 1..n・`tsumogiri`・`riichi`）
- `seats[seat].melds: Meld[]`（**順序情報なし**）
- **全席横断の時系列が存在しない**（東の3打目と南の2打目の前後が復元不能）
- **ツモ牌（draw）を持たない**（手出し/ツモ切りは `tsumogiri` フラグのみ）

タイムラインが必要とするもの:

1. 全席横断の**グローバル順序**（打牌＋鳴きを1列に）
2. 打牌ごとの**ツモ牌**（任意。手出し/ツモ切りの意味づけ・表示に使う）
3. 鳴きを時系列の**任意位置**に置けること

→ **静的スナップショット と イベント列 の二重表現をどう扱うか**が最大の設計判断。

## 3. データモデル（`[決定]` = 案A イベントログ正典）

> **[決定]** 案A を採用。Kifu に時系列 `timeline: TimelineEvent[]` を追加し**正典**とする。
> 盤面（席ごと river/melds）と巡目は timeline から**導出**する。**ツモ牌 `draw` を保存する（[決定]・任意項目、不明は null）**。
> 案B/案C は検討したが不採用（下に記録として残す）。

### 案A: イベントログを正典化（採用）
Kifu に時系列 `timeline: TimelineEvent[]` を追加し、**これを正典**とする。盤面（席ごとの
river/melds/hand の一部）は timeline から**導出**して描画・採点に渡す。

```ts
// 追加スキーマ（イメージ）
const DiscardEventSchema = z.object({
  kind: z.literal("discard"),
  seat: SeatSchema,               // 絶対席
  draw: MaybeTileSchema,          // ツモ牌（不明/なしは null）
  tile: MaybeTileSchema,          // 捨て牌
  tsumogiri: z.boolean().default(false),
  riichi: z.boolean().default(false),
  confidence: ConfidenceSchema.default(1),
});
const MeldEventSchema = z.object({
  kind: z.literal("meld"),
  seat: SeatSchema,
  meld: MeldSchema,               // 既存 Meld を再利用
});
const TimelineEventSchema = z.discriminatedUnion("kind", [DiscardEventSchema, MeldEventSchema]);
```

- **利点**: 順序入替・巡目・鳴き割り込みが自然。手順タブの操作が 1 配列の並べ替えに帰着。
- **欠点**: 盤面描画・採点・AI取り込みが timeline 依存になり**影響範囲が広い**。既存 `seats[].river` を残す場合は同期が要る。
- **移行**: 既存牌譜は timeline を持たないので、席ごと river/melds から**輪番（東→南→西→北を1巡）仮定**で timeline を生成する（`[未確定]` 前後関係は完全復元不能なので輪番を既定とする）。

### 案B: 既存の席ごと保持のまま、順序を全体化（不採用・記録）
`Discard.order` を**全体で一意な連番**にし、`Meld` にも `order` を付ける。timeline は
「全席の river ＋ melds を order でソート」して都度導出。`draw` は `Discard` に任意追加。

- **利点**: 盤面描画・採点は**現行のまま**。追加は order の意味変更＋draw のみ。
- **欠点**: 「席ごと配列」と「全体順序」の**二重管理**（並べ替え時に両方更新）。整合が崩れやすい。
- **移行**: 既存 order（席内）から輪番仮定で全体 order を振り直す。

### 案C: スキーマ非変更・導出のみ（不採用・記録）
スキーマは変えず、**輪番仮定でタイムラインを画面上だけ再構成**。編集結果は席ごと
river/melds に**書き戻す**。`draw`・鳴きの厳密な割り込み順は保持しない。

- **利点**: 背骨を変えない。最小。
- **欠点**: ツモ牌が保存できない／鳴きと打牌の厳密な前後が保存できない（＝要件の一部を満たせない）。

> **[決定] 段階移行**: 案A のスキーマを**追加（optional）**し、盤面/採点は当面
> timeline→席ごとへ**導出関数**を噛ませて現行コードを温存する。既存牌譜（timeline 無し）は
> 席ごと river/melds から**輪番（東→南→西→北）仮定**で timeline を生成する（`[決定]`。
> 厳密な前後は復元不能なため輪番を既定とし、ユーザーが手順タブで直せる）。

## 4. 巡目の導出（`[決定]` ロジック）

- 親（`meta.dealer`）の**打牌イベントを数えて** 1巡目・2巡目…と区切る（プロトタイプと同じ）。
- 並べ替えると区切りは自動再計算。UI は各巡の先頭に「N巡目」セパレータを描く。
- `meta.junme`（最終巡目）は timeline から算出して整合させる（手入力値は上書き or 検証）。

---

## 5. 編集操作 → データ反映

| 操作 | 反映 |
|---|---|
| 行のドラッグ並べ替え | timeline 配列の要素移動（案A）／order 振り直し（案B） |
| 席タップ | event.seat を東→南→西→北で巡回 |
| ツモ牌/捨て牌タップ | 牌ピッカーで tile/draw を設定。ツモ切り時は tile=draw に連動 |
| 手出し/ツモ切り切替 | tsumogiri トグル。ツモ切りなら tile=draw |
| 鳴き 種別/鳴き元/牌 | Meld を編集（暗槓は from=null） |
| ＋打牌 / ＋鳴き | 末尾（or 選択位置）にイベント追加 |
| 削除 | 当該イベント除去 |

- **AI に推測させない原則は維持**: 読めない牌は `tile:null`+`confidence:0`。ツモ牌 `draw` も不明は null。
- 反映後は必ず `KifuSchema.parse` で再検証してから保存（信頼ゲート）。

## 7. 影響範囲

- `packages/schema`: 案A/B で **スキーマ追加**（optional で後方互換）。`toAbsoluteSeat` 影響なし。
- `packages/ui`: timeline↔盤面の**導出関数**（案A）、巡目算出、tegiri/tsumogiri 表示ロジック。
- `apps/web`: 編集画面に手順タブ・タイムライン UI・ドラッグ・ピッカー結線。

- 採点（`@rigel/ui/score`）: 案A なら river 導出に依存。案B/C は現行のまま。

## 8. 決定事項 / 残論点

**[決定]**
1. データモデル = **案A（イベントログ `timeline` 正典・盤面/巡目は導出）**。
2. **ツモ牌 `draw` を保存する**（任意項目・不明は null）。
3. 既存牌譜の移行 = **輪番（東南西北）仮定で timeline 生成**（手順タブで手直し可）。
4. ナビ = **盤面/手順のタブ切替**。
5. **（2026-07 追記・2026-07-16 更新）盤面編集は timeline を seats の内容で常時同期**する
   （`reconcileTimeline` in `@rigel/ui`）。盤面タブで河/鳴きを編集すると seats だけ更新され、
   timeline が非空だと手順ナビに反映されない／保存時に消える不具合があったため、往復整合
   （盤面→timeline 方向）を実装。規則（2026-07-16 に「輪番へ正規化」から**並び保持**へ変更。
   鳴きの後の打牌は輪番＝東南西北順にならないため、正規化すると鳴きの手順・手動並べ替えが
   盤面編集のたびに壊れていた）:
   - **打牌の既存の並びは保持**する。牌・リーチ/ツモ切り・鳴き印の内容は seats（編集面）から取り直す。
   - 盤面で**増えた打牌**は「輪番で先行すべき打牌（前の巡・同巡の先行席）の直後」へ差し込む
     （既存が輪番どおりなら従来の巡目インターリーブと同じ結果）。
   - ツモ牌 `draw` は「席＋席内index」で旧 timeline から引き継ぐ。
   - 鳴きは内容を seats から、位置（アンカー＝直前の打牌）を旧 timeline から引き継ぐ。
   - **手順タブでの手動並べ替えは盤面編集を挟んでも保持される**。
     timeline が空（新規牌譜）のときは何もしない（導出が既に巡目順）。
6. **（2026-07-11 追記）最終ツモ（ツモ和了牌）は timeline の打牌イベントにしない。**
   打牌イベントで表すと再生で和了牌が河へ捨てられる誤演出になる。正は `Kifu.agari`
   （winner / from=null がツモ / winTile）で、ビューアは `frame.tsumoWin`（`@rigel/ui`
   playback.ts の `buildPlaybackFrame` が導出）を受けて和了牌を手牌の横に離して描画する
   （スナップショット手牌=14枚なら該当1枚を分離、編集済=13枚なら14枚目として追加描画）。
   **表示タイミングは「再生で末尾に達したとき（=atEnd・和了演出と同じ発火条件）」のみ**
   （当初は初期の全表示でも出す仕様だったが、2026-07-11 に変更）。
   timeline に「打牌なしのツモ」イベント種別を足す案は、歩幅（打牌単位）の意味論に波及する
   ため見送り（必要になったら再検討）。
   なお卓中央にはツモ表示を置かない（ツモは手牌へのフライイン演出で分かる。中央はドラ常設
   ＝web/mobile 共通）。
7. **（2026-07-11 追記・同日更新）再生ステップは半歩刻み（ボタン駆動・タイマーなし）。**
   次ボタンを押すごとに ①ツモ牌が手牌右端のスロットへフライイン（盤面は1手前のまま）→
   ②打牌が河へ drop し手牌が理牌される、を半歩ずつ進める。前ボタンはその逆
   （打牌を引っ込めてツモ表示 → さらに前の手の完了状態）。ツモ切りも同じ半歩刻み。
   **ツモ牌が不明な手（draw=null・未編集の timeline なし）は半歩なし＝1押し1打牌。**
   **和了も半歩**: 末尾でさらに次ボタンを押すと、ロンは和了演出（ダイアログ）が開き、
   ツモは先に和了牌をツモる（winDraw フェーズ＝右端スロットへ中央からフライイン）→
   もう1押しで和了演出。前ボタンは逆（演出を閉じる → 和了牌を引っ込める）。
   **ツモ和了牌は手牌本体には常に混ぜない**（スナップショット手牌=和了牌込み14枚型でも
   表示は1枚抜いた13枚型。winDraw で初めて現れる。初期の全表示・末尾ジャンプでも出さない）。
   （当初はタイマー（STEP_DRAW_MS/AGARI_DELAY_MS）で自動進行だったが、ボタン駆動へ変更し両定数とも廃止。）
   置き場: **ツモ和了牌の手牌からの除去は `buildPlaybackFrame` の viewKifu 導出**
   （卓面・和了シート・情報パネルの全消費者で一致させる）、スロット分割（`splitDrawnTile`＝
   理牌＋スロット振り分けのみで手牌からは抜かない）・半歩の有無（`stepHasDraw`）・
   **フェーズ→表示物の写像（`stepDisplay`）**は `@rigel/ui` playback.ts。各ビューアが
   持つのはフェーズ state とボタンハンドラだけ（@rigel/ui は React 非依存のため hooks は置かない）。

8. **（2026-07-13 追記）鳴かれた捨て牌は `calledBy` で表す。**
   ポン/チー/カンで持っていかれた捨て牌は、`Discard`・`DiscardEvent` の `calledBy`
   （鳴いた席。null=鳴かれていない。既定 null＝後方互換）で記録する。
   **牌は河に残して薄表示**（opacity 0.38・`data-called`）にする（巡目・打牌順を保つ案を採用。
   河から外す案は「何を捨てたか」と巡目が失われるため不採用）。
   - **盤面タブ（2026-07-16 更新）**: 捨て牌ピッカーの「鳴かれた」席選択行は廃止（捨て主は
     選んだ牌から自明）。捨て牌から鳴く導線は「鳴き種別（チー/ポン/カン=大明槓固定）→
     鳴いた人（捨て主以外・既定=下家・選手名優先）→ 牌選択=**鳴いた人がその後に切った牌**」
     （`callDiscard`＝@rigel/ui 共有。from=捨て主・calledBy=鳴き主・切った牌は鳴きの直後に挿入）。
     鳴かれた捨て牌を開き直すと選択状態を復元（`discardCallOf`）し、選び直しは**置き換え**
     （重複作成しない）。河の追加ピッカーに鳴き行は出さない（鳴きは捨て牌タップに集約。
     配牌の追加ピッカーには鳴き元の無い鳴き＝暗槓等の作成導線を残す）。
   - **手順タブ（2026-07-16 更新）**: 打牌行の「鳴き」ボタンは順送りではなく選択メニュー
     （なし/他3席・選手名優先）。鳴いた人を選ぶと**鳴き行＋鳴いた人の打牌行（切った牌は
     後で選ぶ）を直後に自動挿入**し、人の変更は連動行ごと付け替え、なしは未入力の連動行を
     取り除く（`setTimelineCall`＝@rigel/ui 共有で web/mobile 同一挙動）。
   - **鳴き行の1行併合（2026-07-16 追記）**: 手順タブの表示は「鳴き＋直後の鳴いた人の打牌
     （同席）」を**1行に併合**する（`timelineRows`）。鳴き行の中で「打（切った牌）」、カン系は
     「嶺上（ツモ）」も選べる（`setMeldDiscard`＝併合対象が無ければ直後に挿入）。行の移動・
     削除・席替えは併合した打牌ごと動く（`moveTimelineRow` / `removeTimelineRow` /
     `cycleEventSeat`）。データは従来どおり鳴きイベント＋打牌イベントの2件（表示だけ併合。
     ポンと打牌で手順が分かれて巡目の関係が読みにくい問題への対応）。
   - 往復整合: buildTimelineFromSeats / reconcileTimeline / timelineToSeats / playback の
     toDiscard がすべて calledBy を通す。
   - AI 取り込み（assembleKifu）は calledBy=null（写真の河に鳴かれた牌は写らない。人が手順で足す）。
   - **再生連動**: 編集済（timeline あり）の再生では、捨てた時点は通常表示、**鳴きが開く瞬間
     （＝次の打牌と一緒）に薄表示へ変わる**（buildPlaybackState: applyDiscard が calledBy を
     伏せて積み、applyMeld が鳴き元(from)の直近の捨て牌へ印を付ける）。timeline の無い
     スナップショット牌譜は静的表示（常時薄表示）。牌が飛んで移動するアニメーションは未実装（後続）。
   - **手順→捨て牌の同期（2026-07-13 追記）**: 手順タブで鳴きの from（〇〇から）/種別（暗槓⇄他）/
     鳴き主（席）を変更・行削除すると、鳴き元の直前の打牌の鳴き印を自動で付け替え/解除する
     （`syncCalledByForMeld`。別の鳴き主の印は壊さない）。盤面の鳴き削除（removeMeld）も
     直近の鳴き印を解除する。
   - **チーの並び選択（2026-07-13 追記）**: 捨て牌ピッカー（web）は「並び」行で 567/678/789 等の
     候補（`chiVariants`＝選んだ牌を含む順子・赤5は位置に残す）から選べる。mobile の鳴き追加
     シートは「左端/中央/右端」チップ（`chiRunAt`／`addMeld` の chiIndex）。未選択時は従来の自動。

9. **（2026-07-16 追記）鳴きの盤面表示は実卓の作法に合わせる**（`meldTileViews`＝@rigel/ui 共有。
   web ViewBoard/BoardTable・mobile BoardTable で同一）:
   - 暗槓: 両端2枚を背面（横向きなし）。
   - それ以外: 鳴いた牌を横向きにし、位置で鳴き元を示す
     （上家から=左端・対面から=左から2枚目・下家から=右端。from 不明=左端＝従来互換）。
   - カン後の嶺上ツモ→打牌は、鳴き直後の打牌行（draw=嶺上牌）で表現する
     （捨て牌からのカンは打牌行を自動挿入。暗槓は手順タブで打牌行を足す）。

## 9. 進め方（合意後）

TDD・縦切りで段階導入:

1. スキーマ追加（timeline / draw）＋ Zod・型・`KifuSchema.parse` 後方互換テスト（Red→Green）。
2. 導出関数（timeline→席ごと river/melds、巡目算出）＋単体テスト。
3. web 手順タブ: 表示のみ（読み取り）→ 並べ替え → 各要素編集 → 追加/削除。
4. 保存結線（PUT /kifu）＋既存盤面エディタとの往復整合テスト（**盤面→timeline 方向は
   `reconcileTimeline` で実装済み。timeline.test.ts / edit.test.ts / 各エディタの往復テスト参照**）。
5. eval/回帰（盤面描画・採点が導出でも一致することを確認）。
