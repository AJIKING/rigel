# Plan: 1枚モード（河写真から四家の手牌も読む）

> 状態: 実装済み（2026-08-01 手前のみ → **2026-08-02 四家対応に拡張**・オーナー指示）。
> 対局終了時に全員が手牌を開けて卓全体を1枚撮れば、手牌用の写真を別に撮らずに済む
> （コアバリュー「撮るだけ」の強化。解析回数は最大 +4 = オーナー了承済み）。

## 構成（ハーネス3段構え）

1. **前処理クロップ**: 卓写真の**四辺の外側の帯**（各家の手牌領域）を切り出し、
   河と同じ回転角で正立させて手牌読みに渡す（`handsFromTableLayout`。回転角は
   riverLayout と共有＝実機検証で直すとき一箇所）。
   帯の厚みは **[未確定] 実画像で要調整**（初期値 40%）。
2. **専用プロンプト** `HAND_FROM_TABLE_PROMPT`: 「一辺の帯から、面が見える直線一列
   （その家の手牌）だけを読む。河のグリッド・壁は無視。伏せ牌しか無い辺は空の手牌。
   null 白旗は従来どおり」。
3. **UI トグル**（mobile 撮影画面・河ピッカー直下）: 文言は **「手牌を含む」**
   （[決定] 2026-08-02 オーナー。説明文にコスト最大+4を明記）。ON で各家の手牌欄を
   まるごと隠す（明示指定の優先は API 側の仕様として残る）。

## 配線

- `AnalysisInput.handFromRiver?: boolean`（明示の hands.bottom があればそちらを優先）
- form フィールド `handFromRiver=true` → StartAnalysisParams → キューのメッセージ →
  RunAnalysisJob → GeminiAnalyzer（クロップ→専用プロンプトで readHand・呼び出し +1）
- client（@rigel/client）は FormData 素通しのため変更なし

## 信頼まわり

- null 白旗・Zod 検証・成功時のみ課金は既存パイプラインのまま（readHand を再利用）
- 画像はクロップも含めメモリ内のみ（R2 に置くのは元の river だけ・従来どおり削除）

## [未確定]（実機で確定して本 Plan に記録する）

- クロップ矩形（下端 40%）の妥当性（手牌が切れる/河が混ざる場合は調整）
- 実写真での手牌読み取り精度（寄り写真との比較。悪ければ eval を組んで
  プロンプト/クロップを調整。判断指標は misreadRate）

## 受け入れ条件

- [ ] handFromRiver + 河写真で手牌呼び出しが1回増え、hands.bottom が埋まる
- [ ] 明示の hands.bottom があれば 1枚モードでも明示側が勝つ（二重読みしない）
- [ ] トグル ON で「あなたの手牌」欄が消え、送信フォームに handFromRiver が載る
- [ ] クロップ矩形は 0..1 の範囲・下端帯（純粋関数でテスト）
