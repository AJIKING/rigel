# Plan: 特訓の開放とランキング — 匿名プレイ・無料1日10回・有料フル保存・ランキング

> 承認: **2026-08-04 オーナー決定**（①ランキング強制表示 ②チート対策必須 ③期間=週間/月間/全期間
> ④無料は種目共通で1日10回 ⑤ダウングレード時は全て閲覧不可）。細部の既定値は本文に明記（変更容易）。
> 関連: [quiz-training.md](quiz-training.md)（現行特訓の確定仕様）/ [タスク分解とPlan運用](../開発ガイド/03_タスク分解とPlan運用.md) / 設計ドキュメント2章
> 前提となる現行実装: 出題はクライアントでシード付き乱数から決定的に生成・クライアント採点。
> サーバ保存は集計のみ（quiz_sessions = kind/total/correct/durationMs/startedDay）。API は3本とも認証必須。

## 1. 目的（[決定] 2026-08-04）

1. **特訓をサインインなしで遊べるようにする**（結果は保存しない）→ 獲得導線
2. **無料ユーザは種目共通で1日最大10回**（現行3回から拡大）。簡単な結果（現行の集計）は保存する
3. **有料ユーザは無制限＋問題・解答・結果をすべて保存**（見直しリストの永続化）
4. **ランキング**: 無料・有料ユーザの検証済み結果から正答率と解答数でランキング化。**参加は強制**
   （表示は公開プロフィール情報の範囲。ユーザIDのみの表示でも可＝オーナー許容）

web / mobile 両対応。

### 収益整合

無料枠は 3→10 に緩和されるが**維持**されるため、402 のアップグレード導線は現行どおり残す。
有料価値は「無制限」＋「フル保存（見直しの永続化）」＋（間接的に）ランキング上位を狙える反復量。

### 匿名プレイの抜け道（許容 [決定] 2026-08-04 に含意）

匿名プレイはサーバを呼ばないため回数無制限。無料ユーザがサインアウトすれば無枠で遊べるが、
**結果が保存されず・ランキングにも載らない**ため実害なしとして許容する。

## 2. ハーネス構成要素

- スキーマ: 回答レコード（QuizAnswerRecord）を @rigel/schema に昇格し、サーバ受け取り時に `parse` で検証
- 制約: ランキングに載せる数値は**サーバ再採点済み（verified）のみ**。クライアント申告値は本人表示専用
- AI 非関与: 引き続き Gemini 不使用。出題・採点・検証はすべて決定的アルゴリズム

## 3. フェーズ構成（独立に出荷可能。この順で縦切り）

### Phase 1: 匿名プレイ（API 変更ゼロ）[決定] 2026-08-04

出題・採点は完全にクライアント側なので、**サーバ変更なし**で実現する。

- web/mobile の TrainingScreen から `!user → サインインしてください` ゲートを外し、
  未サインイン時は `startQuizSession` / `finishQuizSession` を**呼ばない**（sessionId なしで状態機械を回す）。
- 開始ダイアログ: 匿名時は直近5回の記録行を出さず、種目説明＋ QUIZ_RULE_NOTE のみ。
- 結果画面: 成績表示＋見直しリストは従来どおり（クライアント状態）。
  末尾に**サインイン導線1行**「サインインすると成績が記録されます」（@rigel/ui に定数化）。
- 計測: quiz_start / quiz_complete は匿名でも送る（PII なし）。
- 既定値: `/training` の noindex は**現状維持**（解除はオーナー判断が出たら別途）。

### Phase 2: 無料枠 3→10 回/日 [決定] 2026-08-04

- `FREE_QUIZ_PER_DAY` を **3 → 10** に変更。数え方は現行どおり
  **種目共通（全 kind 合算）・開始時に1回消費（途中離脱も消費）・JST 0時回復・サーバ強制**。
- 402 経路（開始ダイアログ内・結果画面のアップグレード導線）は**現行どおり維持**。
- `packages/schema/src/plan.ts` の定数変更＝料金表変更。設計ドキュメント7章と quiz-training.md の
  該当 [決定] に転換の追記を同一コミットで行う。
- 無料の保存は現行のまま（quiz_sessions の集計行）＝「簡単な結果」。

### Phase 3: 有料フル保存（問題・解答・結果）[決定] 2026-08-04

- **問題スナップショット方式**: 終了時（PATCH）に集計に加えて
  `records: QuizAnswerRecord[]`（問題データ＋選んだ回答＋○×）を送る。
  - シードリプレイでの**復元**は採らない（生成エンジン改修で過去シードの再生結果が変わり履歴が壊れる）。
    シードは Phase 4 の**検証**にのみ使う。
  - サイズ目安: 60秒で最大数十問 × 1問数百B → 1セッション数KB。D1 の JSON カラムで許容。
- スキーマ: `QuizAnswerRecordSchema` を @rigel/schema に追加（型は既存 @rigel/ui QuizAnswerRecord を移管）。
  サーバは `parse` 通過分のみ保存。
- 保存先: **quiz_sessions に `records` JSON カラム追加**（新テーブルなし → 退会カスケード追加不要）。
- 保存条件: plan が next/pro のセッションのみ records を保存。無料からも受け取るが
  検証（Phase 4）に使ったのち**保存しない**。
- **ダウングレード時は全て閲覧不可**（[決定] 2026-08-04 ⑤）: データ行は保持し、
  **閲覧 API が現在の plan を見て records を返さない**（再アップグレードで閲覧復活）。
  完全削除はしない（退会時は従来どおり全削除）。
- 閲覧 UI: マイページ特訓タブの履歴行タップ → セッション詳細（見直しリストと同構造）。
  web = `/mypage/training/[sessionId]`、mobile = MyTraining からの詳細画面。**本人のみ**。
- API: `GET /quiz/sessions/:id` を追加（requireAuth・所有者以外 404・records は有料時のみ）。

### Phase 4: ランキング [決定] 2026-08-04

#### 4-1. チート対策（必須 [決定] 2026-08-04 ② → 案B シードリプレイ検証）

- `POST /quiz/sessions` が**サーバ発行シード**を返し `{id, seed}`、quiz_sessions に `seed` を保存。
  クライアントは受け取ったシードで従来どおり生成・進行（匿名はローカル乱数のまま・検証対象外）。
- `PATCH` で records（全回答）を受け取り、サーバが**同じ生成器をシードから再実行して再採点**。
  サーバ採点値と `verified=1` を保存し、**ランキングは verified セッションのみ**集計。
  無料ユーザも検証は行う（records はその後捨てる）。
- **バージョンスキュー**: クライアントがエンジン版数（@rigel/ui の `QUIZ_ENGINE_VERSION` 定数）を送り、
  サーバと不一致なら `verified=0`（保存はする・本人の履歴グラフには載る・ランキングにだけ載らない）。
  スキューはデプロイ直後の短時間のみで許容。
- **所要時間のサーバ強制**: 開始（createdAt）→終了の実時刻が 60 秒未満の finish は verified=0。
  外部ソルバ併用は検出不能（低ステークスとして許容。オーナー了承済み=チート対策は再採点＋時刻強制の範囲）。
- **エンジン共有**: 生成器・採点器は @rigel/ui の純粋モジュール（React 非依存）。api から直接 import
  できるならそれで足り、依存が絡むなら純粋部分をサブパス export に切る（新パッケージは切らない・既定値）。
- 検証 CPU: 同一シードなので棄却サンプリングの試行回数もクライアントと同一。実測して Workers CPU に
  収まらなければ Queues 経由の非同期検証へフォールバック（ランキング反映が遅延するだけで UX 不変）。

#### 4-2. ランキング仕様

- 集計軸: **種目別**（クロス種目合算は [決定] 2026-07-27 でグラフにおいて否定済み。整合）。
- 期間: **週間（JST 月曜起点）／月間（JST 月初）／全期間**の3タブ（[決定] 2026-08-04 ③）。既定=週間。
- 指標2本（[決定] 2026-08-04 ①「正答率と解答数」）:
  1) **正答数ランキング**: 期間内 correct 合計
  2) **正答率ランキング**: 期間内 correct/total。**最低解答数 total ≥ 50**（既定値）で少数プレイの
     100% を排除
- 表示: 順位・displayName・handle（→ /u/handle へリンク）・値。**上位 N=50**（既定値）＋
  サインイン時は**自分の順位行**（圏外でも表示）。
  オーナー許容は「ユーザIDのみでも可」だが、常時公開のプロフィール情報（displayName/handle）を
  使う方が UX が良く公開範囲も同一なのでこちらを既定とする。**userId そのものは返さない**（7-3 整合）。
- **参加は強制**（[決定] 2026-08-04 ①）: オプトイン/アウトなし。users へのフラグ追加なし。
  quiz-training.md の [決定]「成績は本人のみ」は本決定により**ランキング集計値の範囲で転換**
  （同 Plan に追記する）。
- 対象: verified=1 のセッションのみ。匿名プレイは保存がないため対象外。

#### 4-3. API・集計

- `GET /ranking?kind=&period=` … **匿名可**（requireAuth なし・RL_READ）。
  返却: `{entries: [{rank, handle, displayName, correct, total, accuracy}], me?: {rank, ...}}`。
- 集計: quiz_sessions の直接集計。新 index `(kind, created_at)`（verified 込みの複合は実測で判断）＋
  Cache API で短期キャッシュ（既定 60s）。規模が出たら日次マテリアライズへ（初版ではやらない）。
- UI: web = `/ranking`（公開ページ・特訓画面とヘッダから導線）、
  mobile = 特訓タブ先頭にランキング導線 → ランキング画面（既定値）。

## 5. リスク

- **チート**: 再採点で申告値改ざんは無効化。外部ソルバ・複数アカウントは検出不能（低ステークス許容）。
- **バージョンスキュー**: デプロイ直後のセッションが unverified になり得る。本人の履歴・グラフには
  影響なし（ランキングにだけ載らない）。
- **検証 CPU**: 再生成＋再採点の実測が必要。超過時は Queues 非同期化で吸収。
- **無料10回化の書き込み量**: 開始=1 INSERT・終了=1 UPDATE ×10/日。RL_WRITE・WAF で受ける。
- **匿名プレイの負荷**: サーバ呼び出しゼロのため無し。
- **records の肥大**: 数KB/セッション × 有料のみ保存。問題なし（監視のみ）。

## 7. 実装ノート（2026-08-04 実装完了時点）

- **設計の要変更点（実装で確定）**: クライアントは完了時に**問題を送らず全回答だけを送る**
  （QuizFinishSchema の answers）。問題はサーバがシードから再生成するので、保存される
  スナップショットは**偽造不能**（クライアント申告の問題を信じる必要がない）。
- 有料フル保存の「シードからの復元」は不採用（生成エンジン改修で過去履歴が壊れる）。
  保存はサーバ再生成スナップショット（quiz_sessions.records JSON）。
- 採点は `gradeQuizAnswer`（@rigel/ui）に一本化し、reducer とサーバのシードリプレイ
  （`replayQuizAnswers`）が同じ物差しを使う。エンジン版数は `QUIZ_ENGINE_VERSION`
  （生成器の出力が同一シードで変わる変更をしたら必ず +1）。
- 検証 CPU の見積り: 生成コスト実測（quiz-chinitsu-ukeire.md: テンパイ 6.3ms / 1向聴 31.7ms /
  牌効率 12.1ms/問）× 60秒で最大数十問 ≈ 最悪 1〜2 秒/セッション。Workers の CPU 上限
  （既定 30s）に対し十分小さいので同期検証のまま（Queues 非同期化は不要と判断。
  本番デプロイ後に p99 を一度確認する）。
- ランキングのキャッシュは Cache-Control ヘッダのみ（匿名 `public, max-age=60` /
  サインイン `private, no-store`）。Cache API・マテリアライズは規模が出てから。
- workspace 依存を1本追加: **apps/api → @rigel/ui**（React 非依存の純 TS。
  quiz-training.md 8章で想定済みの参照）。外部ライブラリの追加はなし。
- 検証: ルートで typecheck / lint / format:check / test / build すべて緑（2026-08-04）。

## 8. 品質パス（2026-08-04 実装直後の4観点レビューと対応）

  完了ペイロードは quizFinishPayload() に一本化（answers/engineVersion の送り忘れ＝静かな
  unverified 化を防ぐ）
- **UX**: 結果画面・マイページ特訓タブにランキング導線（web/mobile）。web ランキングの初期取得

  ちらつき解消（mobile）。サインイン導線は動詞形「サインインして成績を記録する」へ。
