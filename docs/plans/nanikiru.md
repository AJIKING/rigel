# Plan: 麻雀何切る問題機能（作成・回答・一覧・マイ管理・共有）

> 状態: **承認済み（2026-07-07）**。本文は合意時点の内容（レビュー3往復の修正を反映済み）。

## 1. 目的（なぜ）

牌譜の「記録・共有」に加え、盤面を素材にした**出題・回答**という2つ目のコアユースケースを作る。
既存の背骨（牌スキーマ・盤面描画・編集部品）を再利用し、全プラン共通機能としてユーザー獲得の入口にする。
AI(Gemini) は関与しない（全て手入力）。

## 2. ハーネス構成要素

**ツール（スキーマ）** が中心（`ProblemSchema` を背骨に追加し全層共有）＋ **制約**（draft の所有者限定・
回答の1人1回・free 20問上限）＋ **検証**（枚数整合・choiceKey の直列化）。

## 3. スコープ

### やること
- 何切る問題の Zod スキーマ（`@rigel/schema`）と共有ロジック（`@rigel/ui`）
- 作成/編集: 出題形式（①何切る=手牌13枚+ツモ ②鳴き判断）、リーチ有無、ルール設定（`RulesSchema` 再利用）、
  局情報（場風・親・本場・供託・巡目・**点数状況**=新規）、ドラ・手牌・4席の河・副露の編集、作者の答え＋解説
- **鳴き判断は「対象席の河の末尾の1枚」を対象にする**（盤面に実際に切られた状態で出題。
  対象は `targetSeat` の席指定のみ・牌は河から導出）。回答は**選択式**（スルー/ポン/チー/カン→鳴く場合のみ切る牌）
  - **（2026-07-14 追記）チーは構成も選ぶ**（`CallAction.chiTiles`。候補=対象牌を含む順子のうち
    残り2枚が手牌にあるもの・既定は最初の候補）。分布キーも構成で分かれる（例 `call:chi:345p:1m`。
    赤5は5に正規化）。旧回答（構成なし）はキー不変で共存。カンの細分（明/暗/加）は引き続き問わない。
- 回答画面: 回答後に**作者の答え＋解説＋回答分布**を表示
- 公開一覧 / マイ何切る（**draft / published の二状態**。公開非公開の概念なし）
- 共有: `/p/[problemId]` URL（web）・OS 共有（mobile）
- 回答集計: **ログインユーザーのみ** D1 に保存（1人1回・再回答は上書き）。未ログインは回答体験のみ（分布に数えない）
- **保存上限: free は draft+published 合算 20問・有料は無制限**（機能自体は全プラン同一）
- web / mobile 同時リリース

### やらないこと
- 点数の自動計算（点数状況は手入力の記録・表示のみ）
- 写真からの問題生成（AI 非関与・画像非保存の前提維持）
- 牌理チェック（チーは上家からか等の検証はしない。作者責任）
- コメント・いいね・ランキング（将来）
- 既存牌譜からの「問題に変換」導線（将来。スキーマはそれを妨げない）

## 4. `[決定]` / `[未確定]` の仕分け

- 依拠する `[決定]`: TS一気通貫／Zodスキーマ背骨／D1+Drizzle／Hono+DDD／点数自動計算しない／画像非保存／個人情報非レスポンス
- 触れる `[未確定]`: なし（toAbsoluteSeat 不要=絶対席で直接入力、AI 非関与）
- 設計ドキュメント2章へ「何切る問題」を `[決定]` として追記してから実装する

## 6. 信頼まわり

- AI 出力: 該当なし（全て手入力。牌は `Tile` 確定値・confidence 不要）
- 課金: Gemini 非使用（解析カウント非関与）。**保存上限のみプラン差**（free 20問・api で 403 判定）
- プライバシー: 回答は user_id 紐付け保存だが **API は集計（choiceKey ごとの件数）のみ返す**。
  draft は所有者以外 404（存在も漏らさない）。email 非レスポンス等の既存原則維持
- 画像非保存: 画像を扱わない

## 7. API 設計（合意済み）

| エンドポイント | 認証 | 内容 |
|---|---|---|
| POST /problems | 必須 | 作成（free は合算20問で 403） |
| PUT /problems/:id | 必須(所有者) | 更新（status 切替含む） |
| DELETE /problems/:id | 必須(所有者) | 削除 |
| GET /problems | 不要 | 公開一覧（published のみ・新着順） |
| GET /problems/mine | 必須 | 自分の一覧（draft 含む） |
| GET /problems/:id | 不要（draft は所有者のみ） | 問題本体のみ。分布は含めない |
| POST /problems/:id/answers | 必須 | 回答 upsert。**レスポンスはシンプル（分布を含めない）** |
| GET /problems/:id/stats | 必須 | 分布（choiceKey ごとの件数+合計）＋自分の回答 |

## 8. 受け入れ条件（= 最初の Red の集合）

- [ ] ProblemSchema: 何切るは「手牌＋副露(3枚換算)＝13枚＋ツモ」でないと parse 拒否／鳴き判断は 13枚相当＋対象席の河末尾が非null・ツモ null
- [ ] ProblemActionSchema: discard(牌+リーチ)/call(種別+切る牌。カンは切る牌null・ポンチーは必須)/pass を検証し choiceKey() が一意直列化
- [ ] problemToKifu() が KifuSchema.parse を通り、pov の手牌が理牌されて描画に乗る
- [ ] api: draft は所有者以外 404／published は認証不要で取得可
- [ ] api: free の21問目の作成は 403（共通文言）
- [ ] api: POST answers は未認証 401・再回答は上書き（分布合計＝回答者数）・レスポンスに分布なし
- [ ] api: GET stats は未認証 401・認証時に分布＋自分の回答
- [ ] web /p/[id]: 回答前は答え・分布を出さない→回答後に答え+解説+（ログイン時）分布。鳴き判断はスルー/ポン/チー/カンの選択式
- [ ] 公開一覧は published のみ／マイ何切るで draft⇔published 切替
- [ ] mobile で作成→回答→分布の一筋が通る
