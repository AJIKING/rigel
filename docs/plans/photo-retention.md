# Plan: 撮影画像の恒久保存（元写真を牌譜・何切るに残す）

> 状態: **承認済み（2026-08-03 オーナー回答反映）**。v1 のオーナー決定:
> - バケット名は **`rigel`**（新規・TTL なし・単一の恒久バケット）
> - **移動はしない**: 送信時から恒久領域へ直接アップロード（tmp→本置き場のコピーは廃止）
> - **削除はデータ削除時のみ**（半荘削除・問題削除・退会。局削除では消さず半荘に残す）
> - 何切るは**解析下書きの自動作成**（解析完了で下書きが残り、写真も紐づく）
> 本 Plan の承認をもってハードルール7（画像非保存）の [決定] を更新する。
> 関連: [async-analysis.md](async-analysis.md)

## 1. 目的（なぜ）

解析に使った撮影写真を牌譜（半荘）・何切るに紐づけて残し、あとから見返せるようにする。

- **検証**: AI の読み取りを元写真と突き合わせて確認・修正できる
- **記録**: 「あの日の卓」が写真ごと残る
- **再解析**: 画像が残るので「もう一度解析」の1日期限（retry_expired）が実質なくなる
- **何切る**: 解析結果が下書きとして自動保存され、画面を閉じても消えない

## 2. 設計（キーと寿命）

バケット `rigel`（恒久・ライフサイクルルールなし）:

```
games/{gameId}/{jobId}/river          … 河写真（恒久。半荘削除で消す）
games/{gameId}/{jobId}/hand_{cam}     … 手牌写真（同上）
games/{gameId}/{jobId}/message.json   … 再解析用のメッセージ控え（同上）
problems/{draftId}/{jobId}/hand|river … 何切るの写真（問題/下書き削除で消す）
```

- **送信順序がゴミを構造的に防ぐ**: ジョブ行 → 半荘行（/下書き行）→ 画像アップロード →
  キュー投入。アップロード失敗はジョブを failed に落とすだけで、参照なしの孤児画像は
  発生しない（すべての画像が必ず半荘/下書きに属する）
- 解析完了（done）で**何も消さない・動かさない**（残すことが機能）。失敗時も残す（再解析用）
- 既存の `rigel-analysis-tmp`（TTL 1日）は移行後に廃止（バインディング撤去）。
  切替時に飛行中の旧ジョブは images_missing で失敗し得る（利用者は実質オーナーのみ・許容）

## 3. スコープ

- やること（v1）:
  - 牌譜: 画像を恒久保存・半荘詳細に「元写真」ビュー（web/mobile）・削除連鎖
  - 何切る: **解析下書き**（`problem_drafts`）を送信時に先行作成し、写真を紐づけ。
    マイページ何切るタブに「解析中/解析失敗/下書き」として並び、開くと編集画面へ流し込み、
    正規保存（problems 行の作成）で下書きを畳んで写真を問題へ引き継ぐ
  - 配信 API は**所有者のみ**（公開半荘・公開問題でも写真は露出しない）
  - プライバシーポリシー改稿
- やらないこと（v1 非対象）:
  - 写真の公開・共有オプション／圧縮・リサイズ／過去解析分への遡及（画像は消えている）
  - 保存容量の上限（解析枠 = 月100/320回で月次増分は有界。コストを見て [未確定]）

## 4. `[決定]` / `[未確定]` の仕分け

- **変更した [決定]**（CLAUDE.md ルール7・AGENTS.md・設計ドキュメントを更新）:
  - 旧: 画像を恒久保存しない（R2 一時保存のみ・処理後削除）
  - 新: 解析に使った撮影画像は恒久保存し、半荘/何切るに紐づける。閲覧は所有者のみ。
    データ（半荘・問題・下書き・アカウント）の削除で必ず消す
- [未確定]: 保存容量の上限/圧縮・写真の公開オプション・解析下書きの保存件数上限

## 5. 信頼まわり

- **プライバシー**: 写真・下書きは所有者のみ。API は他人・未ログインに 404（存在も漏らさない）
- **削除の責務**: 半荘削除・問題削除・下書き破棄・退会の全経路で R2 + D1 を掃除
  （退会は D1 カスケードだけでは R2 が残るため、削除前に写真プレフィックスを掃除する）
- **課金**: 変更なし（写真保存は解析成功の副産物）
- **Zod**: 下書き Kifu は書く前・読む後とも KifuSchema 検証（現行 result.json と同じ規律）

## 6. 受け入れ条件

- [ ] 解析送信で画像が `games/{gameId}/{jobId}/` に入り、done/failed とも残る
- [ ] GET /games/:id/photos は所有者に一覧、他人に 404。配信は contentType 付き
- [ ] 半荘削除・退会で写真が消える（局削除では消えない）
- [ ] 再解析が TTL に依存しない（半荘がある限り retry 可能）
- [ ] 何切る: 送信で下書きが先行作成され、完了で下書きに解析結果が入り、閉じても
      マイページから開ける。正規保存で下書きが畳まれ写真が問題に引き継がれる
- [ ] 問題削除・下書き破棄・退会で何切る写真が消える
- [ ] web / mobile: 半荘詳細の「元写真」・何切るの下書き導線
- [ ] プライバシーポリシーが新仕様を記載
